# Independent Arc-Morph task-design review

## Decision and scope

Accept as a source-grounded, execution-gated task design and finite offline synthetic-contract artifact. No unresolved blocker was found within this scope after the corrections below. Final release still requires the author to freeze the complete inventory and run the delivered-tree verification commands after all edits.

This review establishes no physical execution, robot or optical performance, physics simulation, fabrication feasibility, safety qualification, source-image reanalysis, mathematical validation or scientific reproduction. The validated runnable whole-paper task count remains zero. The evaluator uses a finite synthetic registry; it is not a live sensor authority, an implemented robot runtime or an operating-system actor/evaluator boundary.

## Evidence preservation

The accepted review contracts were compared directly. Every original field in the ten source facts, twenty coverage records, ten source-conflict cards, fourteen unknown cards and eight source-outcome rows is preserved. Eleven accepted-review document hashes match the provenance receipt. This is an audit of the accepted review contracts, not a new reading of source PDFs or archive contents.

All seven physical route families and 31 operation templates remain represented. CS1, CS2, CS3 and CS4 retain distinct family identities and ground, rigid and sheared qualitative slots. PP_PREP retains identified stock, fabrication handoff, explicit dependency-ordered per-edge folding and baseline custody. PP_RIGID contains exactly eight source-aligned configurations on one specimen and one stock parent. PP_SHEAR remains qualitative, with no invented load magnitude, stiffness result or quantitative success predicate. The six nonmanual dispositions, two auxiliary dispositions and twelve asset groups remain explicit. The source's single measurement set is not relabeled as independent replication.

Both 383.63 mm and 383.65 mm source readings remain unresolved. Theory example values do not become physical drawing defaults. Source radii remain evaluator-facing historical observations, distinct from new measurements and model predictions. No source PDF, figure, image, archive or source-model code is an export member.

## Resolved findings

1. IR01, capture identity binding: the first version accepted unrelated camera IDs and the same lens for both views. Current guards require each capture to match its role's independently supplied current camera/lens identity-revision token. Both device pairs and both reference identities must be distinct; calibration must bind the current references and all nine revision components. Regression tests exercise unrelated devices, aliases, reference mismatches and every stale component.
2. IR02, actual-fixture unmount: the first version selected R22/R30 solely from self-declared record fields. The corrected helper requires an independent current mount, matches fixture kind, fixture ID, specimen ID and lease ID, and requires mounted state. All supported-unload evidence remains mandatory. Wrong actual fixture, stale lease, wrong specimen, already-unmounted state and incomplete release are rejected.
3. IR03, scoped inference gates: U11 and U14 initially applied to all associated operations. U11 now gates applicable source-geometry/model claims, while U14 gates historical raw correspondence. Legitimate new-image observation extraction is not blocked solely by those unrelated claims. Scoped C01/C04 geometry and C02/C07 model/raw gates remain tested.
4. IR04, sibling binding: R11 now consistently includes A08, A09 and A10. The scene task ID is v2 and PP1-to-PP is an explicit alias. All 31 operation asset sets, concrete primary/control targets and 62 primary/control selectors agree. Six contextual R19/R22/R30 selectors match actual nominal fixture classes and target objects. Every reviewed pose remains unqualified and every physical-execution flag false.

## Reopened paired review

The scene semantic files changed after the initial task freeze, so that earlier paired receipt and task ZIP were superseded. The review was reopened against the repaired scene contracts before any new release was accepted.

5. IR05, fabrication custody: the former R06 selector referred to the inspection station even though R06 occurs at the fabrication safe-output handoff before R03 transport. The retained R06 names now select A04 fab.load_dock and fab.job_token_slot. The task explicitly declares the dock's dual input/safe-output role. This is a nominal station correction, not service qualification.
6. IR06, state registry drift: states.json had outdated asset sets for R11, R18 and R19. Every R00-R30 state asset set now agrees with the canonical operation-binding contract, including reverse asset links on the scene side.
7. IR07, configuration scope: configuration_candidate could previously append R13 to a cardstock rigid-demo or corner-mount state. The repaired guard requires PP family and rigid_metrology mount. Cardstock R27 remains expressly metadata-only; a generic configuration call cannot substitute for it.

The strengthened independent tests verify R26/R27's separate rigid-demo support and handle, the refined R10 mount/bolt, R13 plate/control, R14/R19 slider/lock and R30 mount/bolt targets, and the six fixture-specific release selectors. They compare every operation's concrete targets with the task mapping, then verify all 66 anchor owners, target membership and nominal coordinates against asset_inventory.json. Synthetic scene guard tests reject wrong-fixture releases, stale leases/revisions, missing load-removal evidence, incomplete attachment separation, unaccounted corner hardware, live tokens and mounted transport; release preserves append-only state. Scene states retain unimplemented-action and unknown-input boundaries.

Nominal generator dimensions remain distinct from the measured bounds/extents of the twenty static specimen variants. None of those surfaces or dimensions supplies fabrication geometry, mountain/valley assignments, fold order or fold motion limits. The task reviewer checked the repaired metadata relationships; independent native/GLB geometry review remains the scene reviewer's separate responsibility.

The renewed receipt pins nine inspected scene semantic files: operation_binding_contract.json, operation_bindings.json, asset_metadata.json, affordances.json, variants.json, asset_inventory.json, specimen_topology.json, semantic_controls.py and states.json. A regression test checks these hashes whenever the sibling package is available. Future paired-task-reference snapshots are deliberately excluded from that set to avoid a circular hash dependency.

## Independent verification

The independent suite defines 54 tests: 33 contract/source/binding tests and 21 export tests. It exercises all 36 finite route/outcome fixtures, exact event and registry binding, every context-field mutation, omission/duplication/reordering, immutable parentage, append-only history, independent device leases, per-edge folding, current calibration, paired-capture custody, source-observation class rejection, separate radii, retry preservation, replacement-series boundaries and safe held closeout.

Export tests run only on disposable copies. They cover deterministic exact-member ZIPs, missing/extra/mutated files, prohibited source-media names, unknown directories, FIFO members, symlinked members/roots/ancestors/destinations, invalid and noncanonical paths, malformed manifest schemas/types/keys/hashes/counts, nonfinite JSON, duplicate manifest keys, repeated or missing ZIP entries, altered member bytes, encrypted flags, nonregular ZIP metadata, binary content and rehashed private paths. The exact export contains 45 reviewed text files plus its manifest. Only agent_visible.json is designated actor context.

The source-review and sibling-contract comparisons use relative sibling names and are optional when those separately distributed directories are absent. They ran with both directories present during this review. The portable task and export tests remain self-contained. The final-tree manifest test is deliberately strict: review edits invalidate a previous manifest and require a new freeze.

Commands from the delivered package directory:

## Remaining boundaries

The symbolic guards do not authenticate real devices or images. No actual actuator, sensor, pixel extraction, qualified crease graph, scientific model or hardware safety interlock is present. Supplied context must still come from independent qualified authority in any future runtime. Nominal scene anchors and static states neither resolve the fourteen unknowns nor grant motion permission. Supported unresolved hold is valid accounting, never completed unloading or permission to move a mounted or loaded specimen. Publication, remote writes and frozen-repository changes are outside this package and were not performed by this review.
