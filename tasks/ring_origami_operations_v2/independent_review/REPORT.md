# Independent review: reprogrammable origami-ring task design

## Decision

Pass as a source-bounded whole-paper mobile-robot **task design**, retaining qualified execution-input gates. No blocking design findings remain in the reviewed version.

The independent finite contract suite passes **48/48** checks. The author's test code was inspected and independently rerun: **10/10** passes. These are static design and mutation checks, not robot execution, safety qualification, physical feasibility, source-result reproduction or runtime-evaluator validation.

## Repairs verified

1. **Measured analysis and torque ancestry.** Quantitative mechanical branches now reach response analysis. Torsion explicitly requires a matched measured element result from the element branch or a traceable supplied measured dataset. Missing parents leave torque blocked while preserving valid geometry observations.
2. **Coupon preparation state.** The standalone crease demonstration now uses accepted printed parts, ending preparation before complete-element assembly. It no longer silently recovers loose facets from a finished element.
3. **Observation location.** Observation is explicitly co-located or remote. The specimen stays mounted at its actual physical station. Reset and unload bind to that active station; service-name changes do not cause transport.
4. **Actual condition transitions.** Each finite condition requires a separately prepared matched specimen or unloaded, observed reconfiguration followed by remounting/readback. Reused paper arrays need actual pin action, and morphology changes need actual support/reconfiguration operations. A class-change guard also prevents intrinsic crease-recipe changes through ring labels alone.
5. **Control applicability.** Qualitative array transformation has separate controls from quantitative array testing. Sliding-facet and other material-specific assembly checks apply only to the relevant physical interfaces.
6. **Unread video truthfulness.** Movie 9 remains unread and explicitly method-bearing. Other unread movies no longer assert verified absence of method-bearing content.

All repairs were inspected in the final contracts. The independent suite includes targeted checks for them, and the author suite includes mutation tests for the principal causal regressions.

## Scope and evidence assessment

The fourteen physical branch templates and three preparation routes retain both the thick resin/TPU route and the separate cardboard-array route. They assign stock handling, fabrication loading/readback/output recovery, inspection, fastening, trimming, folding, transport, fixture mounting, configuration changes, acquisition handling and cleanup to the robot. Enclosed device processes and analysis are separately owned. Receipt-only specimens cannot earn fabrication credit.

The [main article](https://www.nature.com/articles/s41467-023-42323-1) supports separate element, group, ring and array families. The packet correctly treats torque as semi-experimental; confines the reported prototype count to its supported scope; distinguishes the two test-service speeds; and retains all seven array angle settings for the two loading classes. Proposed robotics and logic applications remain unmeasured schematic scope.

The [SI](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41467-023-42323-1/MediaObjects/41467_2023_42323_MOESM1_ESM.pdf) supports the assembly interfaces and the additional physical families. Source direction/caption and landmark ambiguities remain explicit, rather than silently repaired. The independently checked rest-angle tuples agree with the tabulated element classes. Missing mechanical and fabrication details remain inputs, not inferred recipes.

Lineage records material and job ancestry, assembly membership, shared components, changing configuration epochs, independent specimens versus repeat attempts, calibrated raw acquisitions and derived parents. The array calculation preserves three width series and their baselines. Failed attempts remain visible; source agreement is not the criterion for honest procedural completion. Actor projection excludes expected outcomes and the reference action sequence, with runtime enforcement explicitly unimplemented.
